# Local GIS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Launch and verify the full local GIS stack on this Mac.

**Architecture:** Use the upstream GeoNode deployment as the baseline and extend its Compose project with storage, tile services, and monitoring. Keep state in named volumes and expose browser-facing services on loopback.

**Tech Stack:** Docker Compose, PostgreSQL/PostGIS, GeoNode/GeoServer, Martin, TiTiler, RustFS, Prometheus, Grafana, Loki, Alloy, Alertmanager.

**Spec:** `docs/superpowers/specs/2026-11-09-local-gis-design.md`

## Global Constraints

- All requested services start with `docker compose up -d` after initial setup.
- Host bindings use `127.0.0.1`. Service credentials live in an ignored `.env` file.
- Pin image versions. Prefer ARM64. Explicitly declare emulation where required.
- Alertmanager acceptance covers local routing and resolution.

## Review Focus

- Missing ARM64 manifest. Inspect selected image manifests before startup and verify any emulated service in Docker Desktop.
- Initialization retries. Repeat bucket initialization and check that existing objects persist.
- Dependency readiness. Start with empty volumes and verify GeoNode and both tile services after their dependencies become ready.
- Private object access. Verify unauthenticated retrieval fails while both tile servers return tile content.
- Transient outage. Stop and restore TiTiler and observe the alert lifecycle.

### Task 1 · GeoNode and PostGIS

**Files:** `compose.yaml`, `.env.example`, `.gitignore`, GeoNode configuration under `config/geonode/`.

- [x] Write a core acceptance check that asserts Compose config renders, GeoNode answers HTTP and GeoServer returns WMS capabilities. Run it before adding services.
- [x] Pin a compatible upstream GeoNode/GeoServer pair and add its required dependencies. Configure PostgreSQL databases for the GeoNode catalog and spatial data, GeoServer routing, persistent volumes, and loopback bindings.
- [x] Run the core acceptance check and publish a small test layer. Verify that the layer can be viewed through GeoNode and fetched through GeoServer.

### Task 2 · Object storage and tile services

**Files:** `compose.yaml`, `config/martin.yaml`, `scripts/init-buckets.sh`.

- [x] Write a check that expects nonempty tiles from Martin for a PostGIS layer and a private PMTiles fixture, and a valid PNG from TiTiler for a private COG fixture. Confirm it fails before the services exist.
- [x] Add RustFS with a persistent data volume, an idempotent bucket initializer for `vector-tiles` and `raster-data`, Martin with PostGIS and S3 sources, and TiTiler with GDAL S3 endpoint and credentials.
- [x] Run the check with small fixtures. Verify anonymous reads fail and the initializer can run again without replacing data.

### Task 3 · Monitoring and acceptance

**Files:** `compose.yaml`, `config/monitoring/`, `README.md`.

- [x] Write a check for healthy Prometheus targets, Docker logs in Loki, and a TiTiler outage alert entering and leaving Alertmanager. Run it before configuring monitoring.
- [x] Add Prometheus and HTTP probes, Loki and Alloy, Grafana with provisioned data sources and a service overview dashboard, and Alertmanager with a local route. Add named volumes for persistent state.
- [x] Run configuration validators and the outage check. Verify the full stack is healthy after restoring TiTiler.
- [x] Restart the stack and re-run the layer and tile checks. Document setup, local URLs, verification commands, and how to configure an external webhook.

## Deployment record

- PostgreSQL 15.18 and PostGIS 3.5.4 ran on aarch64. GeoNode and GeoServer used their AMD64 images.
- Database initialization runs as a retryable Compose service. Docker Desktop rejected direct execution of the host-mounted database init script.
- GeoNode published dataset 2. GeoServer returned a nonblank WMS PNG, and the dataset and map survived a full stop and start.
- Tile checks covered dynamic PostGIS, private PMTiles and private COG. Restart checks confirmed that the fixtures persisted.
- Prometheus, Alertmanager, Loki and Alloy configuration validators passed. Runtime checks covered all nine probes, fifteen scrape targets, GeoServer logs in Loki, the provisioned Grafana dashboard and the TiTiler alert lifecycle.
