# Локальна ГІС-інфраструктура

## Мета

Розгорнути на цьому Mac повний ГІС-стек для зберігання, публікації та перегляду просторових даних, обслуговування тайлів і моніторингу. Після початкової підготовки налаштувань усі компоненти запускаються командою `docker compose up -d`.

## Варіанти запуску

- Повний стек за замовчуванням. Усі сервіси доступні після одного запуску. Це вибір користувача.
- Моніторинг в окремому профілі. Економить ресурси під час роботи з ГІС, але для повного запуску потрібен додатковий прапорець.

## Сервіси й потоки даних

- PostgreSQL із PostGIS зберігає каталог GeoNode та просторові шари в окремих базах одного інстансу. Пара GeoNode і GeoServer використовує сумісні образи та необхідні залежності штатного Docker-розгортання GeoNode.
- GeoNode надає вебінтерфейс каталогу й карти. GeoServer публікує шари з PostGIS і обслуговує їх перегляд у GeoNode.
- Martin генерує векторні тайли з доступних йому таблиць PostGIS і читає готові архіви PMTiles із приватного бакета RustFS. TiTiler читає COG з окремого приватного бакета RustFS.
- Prometheus збирає доступні метрики й перевіряє доступність ключових HTTP-сервісів. Alloy передає журнали контейнерів у Loki. Grafana отримує налаштовані джерела Prometheus і Loki та оглядову панель.
- Prometheus передає сповіщення про недоступність сервісів в Alertmanager. Для першого локального запуску передбачено перегляд в Alertmanager і локальний тест маршрутизації. Зовнішню доставку можна налаштувати через webhook після вибору каналу й надання його параметрів.

## Межі локального стенда

Порти, потрібні для браузера та локальних клієнтів, прив'язуються до `127.0.0.1`. Внутрішні залежності доступні у мережі Compose. PostgreSQL, дані GeoNode та GeoServer, RustFS і стан моніторингу зберігаються в іменованих томах. Перший запуск створює необхідні бакети. Локальні облікові дані задаються через файл середовища, виключений із Git. Образи фіксуються за версіями. Пріоритет мають образи ARM64, а для залежностей без ARM64 перевіряється запуск через емуляцію Docker Desktop.

## Критерії приймання

1. Compose-конфігурація проходить валідацію. Всі довготривалі контейнери стартують, а одноразова ініціалізація завершується успішно.
2. Тестовий просторовий шар публікується через GeoNode та переглядається на карті через GeoServer.
3. Martin повертає тайл із PostGIS і тайл із PMTiles у RustFS. TiTiler повертає растровий тайл із COG у RustFS.
4. У Grafana видно метрики й журнали. Контрольована недоступність сервісу породжує сповіщення в Alertmanager, а після відновлення воно переходить у стан resolved.
5. Після перезапуску зберігаються тестові дані. README описує початкову підготовку, запуск, локальні адреси та перевірки.

На момент підготовки специфікації Docker CLI доступний, але поточна сесія отримує помилку доступу до Docker-сокета. Для приймальних перевірок потрібен доступ до Docker Engine.
